# OZLedger 当前架构

最后核对：2026-09-23

## 运行边界

生产环境的唯一数据源是腾讯云服务器上的 MySQL。前端静态文件和 Node API 也运行在同一台服务器上：

```text
浏览器
  -> Nginx :80
       -> 静态文件 /opt/ozledger-app/dist
       -> /api -> Node/PM2 127.0.0.1:8787
                         -> MySQL 127.0.0.1:3306 / ozledger
```

生产 `.env` 不进入 Git，也不由发布脚本覆盖。当前已从服务器确认的关键配置是：

```env
DB_CLIENT=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=ozledger
```

## 数据安全策略

系统使用“完整备份 + 增量审计”的混合策略：

1. 每次数据写入前生成完整 JSON 备份；
2. 数据库中的 `audit_logs` 记录动作、时间、摘要和备份路径；
3. `data/change-log.md` 保留人类可读的历史记录；
4. 每次生产部署前调用本机 API 导出一份 `pre-deploy-*.json`；
5. 数据库写入失败时不应切换到另一套数据库继续写入。

“增量”只用于追踪和审计，不替代完整备份。这样可以回溯每次变更，也可以在审计日志损坏时用完整备份恢复。

## 开发与发布原则

- 本地只做代码开发和静态检查，不把本地 SQLite 当作生产数据源。
- 生产构建在腾讯云服务器上完成。
- GitHub Actions 只负责把代码传到服务器并触发服务器端部署。
- `.env`、MySQL 数据和 `data/` 永远不提交 Git，也不被 SCP 覆盖。
- 生产 MySQL 不可用时，API 启动或请求应失败，不允许静默写入 SQLite。
